# КОМ СЕРВИС 58 — передача проекта в Codex

## Что сделано
Многостраничный адаптивный сайт HTML + CSS + JS, 16 страниц и SEO-карта, изображения WebP, cookie-баннер с отдельными настройками, отдельные страницы политики персональных данных, согласия, Cookie, реквизитов; формы с серверным обработчиком PHP и MAX Bot API, защита от простых спам-отправок, SQLite для первичной записи заявки на российском сервере. Кнопка прямого чата MAX активируется после заполнения настройки. Текущий домен **bioservice58.ru**.

## Важно: статус
Файлы подготовлены, но **сайт не развёрнут**, реальные заявки ещё **не поступают**. Активировать обработку можно после настройки MAX-бота и подтверждения российского хостинга. Нельзя обещать юридическое соответствие без проверки фактических настроек и реквизитов. Генерированные иллюстрации являются демонстрационными, а не фото реальных работ.

## Порядок развёртывания
1. Сохранить резервную копию старого сайта, его БД, WordPress, `.htaccess`, всех URL, метрик и SEO. **Не удалять старый сайт до готовности тестового.** Проверить список прежних URL и настроить 301-редиректы для существующих страниц.
2. Подготовить хостинг в РФ с HTTPS, **PHP 8.1+**, расширениями **curl**, **pdo_sqlite**, **mbstring**, правами записи в `private/`. Предпочтительно DocumentRoot `public_html`, файлы сайта в нём. Настроить запрет доступа к `/private` с помощью Apache; при nginx — отдельное правило `location ^~ /private/ { deny all; }`. Ещё лучше перенести `private` за пределы DocumentRoot и обновить пути к конфигу.
3. Создать MAX-бота через MAX для бизнеса, получить токен, добавить бота в **закрытый рабочий групповой чат**, где владелец получает уведомления, и узнать его `chat_id`. Бот не может быть добавлен в личный диалог владельца. Не используйте публичный канал для персональных данных.
4. Скопировать `private/config.example.php` в `private/config.php` и заполнить `max_bot_token`, `max_chat_id`, `max_contact_url` (проверенную публичную ссылку на MAX), `host_in_russia_confirmed => true` **только после фактического подтверждения**. Секретный конфиг **не коммитить в репозиторий**.
5. Проверить `/api/status.php` — должен вернуть `{"ready":true,...}`. Отправить тестовую заявку с отдельным согласием. Убедиться, что в MAX пришло сообщение и в SQLite изменился `delivery_status` на `delivered`.
6. Проверить реальную отправку на смартфоне, ошибку API при отключённом MAX, невозможность получить `/private/config.php` и `/private/leads.sqlite`, доступность страницы Политики из футера и формы, работу Cookie-баннера и изменение настройки.
7. После теста заменить временные иллюстрации реальными фотографиями и подтверждёнными отзывами, если имеются. Проверить любые заявления об оборудовании Puzzi 10/1, гипоаллергенных составах и наличии разрешительных документов; получить копии применимых деклараций и сертификатов. Не выдавать изображения за реальные результаты.
8. Сверить **оператора Каргина Михаила Михайловича** с заказчиком. Заполнить подтверждённые ИНН, ОГРН/ОГРНИП, статус, адрес, контакт для требований по ПД, срок хранения заявок, обработчиков, договоры поручения обработки, правовые основания. Обновить текст политики и отдельного согласия. Проверить необходимость уведомления РКН, локализацию ПД, передачу MAX и любые внешние сервисы. До этой проверки юридические материалы — проекты.
9. Подключить аналитику **только** после проверки Cookie/согласий: сейчас в архиве **нет** встроенной аналитики. Не добавлять сторонние счётчики без обновления политики.
10. Протестировать sitemap.xml, robots.txt, canonical, адаптивность, скорость, формы, 404 и редиректы старых страниц. Выпустить релиз и наблюдать за ошибками PHP и доставкой заявок.

## Архитектура
- `/index.html` — главная.
- `/{slug}/index.html` — каждая страница услуг, компании, бизнеса, контактов и документов.
- `/assets/style.css`, `/assets/main.js`, `/assets/img/` — фронтенд и графика.
- `/api/status.php` — сообщает фронтенду, подключена ли обработка заявок, и публичную ссылку на MAX.
- `/api/lead.php` — принимает валидированную форму с согласием, сохраняет заявку в SQLite и отправляет текст через `POST https://platform-api2.max.ru/messages?chat_id=...` с `Authorization` токеном.
- `/private/config.example.php` — образец конфигурации, **без секретов**.
- `/private/leads.sqlite` — появится автоматически после первой заявки, хранит персональные данные. Обязательно резервное копирование и ограничение доступов. Для долгосрочного эксплуатации нужен внутренний интерфейс удаления/сроков хранения и мониторинг статуса pending.

## Особые ограничения
- Реальная доставка не тестировалась: токен и ID рабочего MAX-чата отсутствуют. При `ready:false` формы отключаются, предлагается позвонить.
- Для прямой кнопки в MAX необходим публичный URL аккаунта/бота; URL не указан пользователем, поэтому не выдуман.
- Прямой бот → личный аккаунт владельца без разрешённого сценария MAX API невозможен: используем закрытый групповой чат.
- Не используйте неправильный email `info@komservice58.ru.com` со старой страницы. Контакт из прежней Политики: `kargin.evrocar@yandex.ru`.
- На некоторых хостингах `AllowOverride` выключен и `.htaccess` не сработает — проверьте прямым запросом.
- У сайта сейчас **нет** защитного CSRF-токена (есть origin/referrer, session rate-limit, honeypot). Для production добавить токен, капчу по необходимости, журналирование согласия, сроки очистки SQLite, ротацию и мониторинг сбоев MAX, резервную очередь при недоступности API.
